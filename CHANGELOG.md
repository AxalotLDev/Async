- Fixed a crash on entering a world with Lithium installed: Mixin refused to load the Lithium lock holders that lived inside the mixin package
- Fixed copper golems locking a golem's chest in another dimension when both chests share the same coordinates
- Stopped synchronizing every method of every fastutil collection and of the vanilla classes whose fields never cross threads
- `/async config reload` now rebuilds the worker pool
- Worker-thread chunk lookups no longer slow down after every `/async config reload`
- Fixed a NullPointerException when a mob's target dies on another worker between two `getTarget()` reads
- An entity removed and re-added during the entity tick pass is no longer skipped for that whole pass
- Fixed a deadlock between block drops and neighbor updates: `addAndRun` now locks the level, not the neighbor updater
- `Block.dropResources` no longer throws on a null level
- Fixed a server freeze when a worker thread reads a chunk that is not loaded
- Worker-thread chunk reads no longer wait on the server thread when no load was requested
- Restored the synchronization narrowing the spray dropped from `BinaryHeap`, `PathNavigation`, `SimpleCriterionTrigger` and `ClassInstanceMultiMap`
- Fixed entities being dropped from chunk-section queries and from the chunk save when two workers moved entities across the same section boundary at once
- Fixed a NullPointerException when a worker thread read an ender dragon's parts while the server thread attached or detached them
- Fixed a NullPointerException when a worker thread read a chunk's entity visibility while the server thread was changing it: the concurrent map probed twice and could call a present key absent
- Fixed a NullPointerException in Lithium's pushable-entity cache when the server thread stopped filtering a chunk section while a worker thread was collecting pushable entities from it
- Added `asyncMods` and `/async config asyncMods add|remove <mod_id|*>`: the mods whose entities Async may tick in parallel. Minecraft entities are always ticked in parallel, `*` covers every mod (`add *` drops the other entries, `remove *` clears the list), an entry that is not loaded or adds no entity type is skipped with a warning, and the effective list is logged once
- An empty `synchronizedEntities` list on NeoForge no longer silently falls back to the default entities
